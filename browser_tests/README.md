# E1 headless browser acceptance

Ці Playwright-тести відкривають **вже задеплоєний staging**, а не запускають локальну копію застосунку. Використовуйте лише тестові/узгоджені активні staging-облікові записи.

## Налаштування один раз

1. Скопіюйте `browser_tests/e1-staging-config.example` у `browser_tests/e1-staging-config` (локальний конфіг ігнорується Git) та вкажіть змінні:
   - `E1_STAGING_URL` — базова URL staging Web App;
   - `E1_USER_ID` і `E1_USER_CENTER_ID` — активний користувач та його ЦН;
   - `E1_FOREIGN_CENTER_ID` — інший ЦН, до якого цей користувач не має доступу;
   - `E1_ADMIN_ID` — активний адмін;
   - `E1_MONTH` — місяць `YYYY-MM` для перевірки.
2. Один раз у `browser_tests/` виконайте `npm ci`, потім `npx playwright install chromium` (для відсутніх системних бібліотек Playwright підкаже команду для вашого Linux-дистрибутива).

## Запуск

З кореня проєкту запускайте `make test-browser`. Тести read-only: завантажують PDF у пам'ять і перевіряють, що користувач бачить лише власний ЦН, адмін може сформувати звіт для вибраного ЦН, а агрегатний режим «Всі центри» не пропонує кнопку PDF.

Тестовий користувач та адмін задаються окремо, щоб не використовувати персональний акаунт. Усі дії лише читають дані; жодні витрати не створюються й не редагуються.
