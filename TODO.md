# План розробки: Керування ЦН, користувачами, матрицею категорій та перехід на MySQL

Використовуй multi_edit.
Не генеруй довгих пояснень своїх дій - лише стисло, що зроблено і причину.

Цей файл є єдиним джерелом правди (Single Source of Truth) для розробки проєкту.
Після кожного етапу проводиться перевірка працездатності та обов'язковий Git-коміт.

**ВАЖЛИВЕ ПРАВИЛО**: Додаток та бот розгорнуті і працюють на VPS, а не в локальному терміналі агента. Локальна система це Windows 11, VS Code з агентом Continue. Тому, якщо потрібно виконати команди перевірки/тестування скриптів або запитів до БД - передавай ці команди користувачеві та чекай від нього відповіді з результатом. Самостійно агент виконує тільки редагування файлів та git-коміти.

Схема БД знаходиться в файлі schema.sql

Також залишаються важливі вимоги щодо 3 режимів роботи:
 - Читання чеків ботом безпосередньо в чаті Telegram (з AI парсингом через Gemini).
 - Telegram WebApp всередині бота.
 - Повноцінний вебдодаток для звичайного браузера.
