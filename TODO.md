## Задачі за напрямками

### A. AI / розпізнавання чеків
- [x] **A1. Валідація «це чек?».** ✅ У `ai_service.parse_receipt_image` промпт розширено полями `is_receipt` (bool) і `document_type`; для не-чека AI повертає `is_receipt=false`. У `handlers/receipts.py` при `false` — файл не зберігається, користувачу показується «❌ Це не схоже на фіскальний чек…», а всім адмінам надсилається фото документа з підписом (користувач, ЦН, тип). Дефолт `is_receipt=True`, якщо AI не повернув поле (щоб не блокувати справжні чеки).

### B. Бюджети та сповіщення про перевитрату
- [ ] **B1. Хелпер підрахунку.** `database.get_category_spent(center_id, category_id, month)` — сума витрат по категорії за місяць.
- [ ] **B2. Попередження ЦН у боті.** Після `add_expense` (бот і webapp) перевіряти spent vs budget по категорії. При перевитраті — повідомлення в чат (active-юзерам ЦН або в групу ЦН): «⚠️ Перевитрата по «{категорія}»: {spent}/{budget} грн».
- [ ] **B3. Сповіщення адміну за порогом.** Таблиця `app_settings(key VARCHAR(64) PK, value VARCHAR(255))` — налаштування додатка, зокрема `budget_alert_threshold` (дефолт 90%). Вкладка «Налаштування» в адмінці для редагування порогу. Анти-спам: окрема таблиця `budget_alerts(center_id, category_id, month, threshold, sent_at)` з `UNIQUE(center_id, category_id, month, threshold)` — адмін отримує сповіщення лише при першому перетині порогу за місяць. Слати через бота. Файли: `schema.sql`, `database.py`, `webapp.py`, `handlers/receipt_callbacks.py`, `config.py`, `templates/admin.html`, `static/js/admin.js`. Позначення про перевитрати в вебдодатку вже є (червоний прогресбар).

### C. Детекція дублікатів
- [ ] **C1.** `database.find_duplicate_expense(center_id, date, amount, category_id, name)` — пошук збігу в межах ЦН. Перед збереженням (бот-картка + `POST /api/expenses`) показувати «Схоже, цей чек уже додано» з опціями «Все одно додати / Скасувати». Файли: `database.py`, `handlers/receipts.py`, `webapp.py`.

### D. Кілька фото / кілька категорій (зміни схеми БД)
- [ ] **D1. Багаточастинний чек (один чек = кілька фото).** Довгий чек не влазить в одне фото разом із підсумковою сумою внизу, тому бот має приймати чек **частинами**, а ШІ розпізнає їх як **один** чек.
  - **Бот:** новий стан `ReceiptState.waiting_for_more_photos`. Перше фото → зберегти у список, показати клавіатуру «➕ Додати ще фото / ✅ Розпізнати чек / ❌ Скасувати». Кожне наступне фото додається у список. По «✅ Розпізнати» — завантажити всі частини й надіслати в Gemini одним запитом → одна картка підсумку (існуючий `render_summary`).
  - **AI:** `ai_service.parse_receipt_images(images: list, valid_categories)` — Gemini приймає кілька зображень в одному `contents=[prompt, img1, img2, ...]`. Промпт: «Це частини ОДНОГО чека (зверху вниз). Об'єднай в один результат; підсумкова сума зазвичай на останньому фото; не дублюй товари при перекритті». `parse_receipt_image` лишити як обгортку `parse_receipt_images([image])` (для веб-завантаження одного фото).
  - **Токени/стиснення:** Telegram уже стискає фото (~1280px, ~1k токенів/частина). `optimize_image_for_ai` **видалено** (мертвий код, був no-op для фото з Telegram).
  - **Зберігання:** таблиця `expense_receipts(id, expense_id, path, sort_order)` з `FOREIGN KEY (expense_id) REFERENCES expenses(id) ON DELETE CASCADE`; `sort_order` = порядок частин. `expenses.receipt_path` **лишаємо** як «головне фото» (перша частина) для зворотної сумісності (читається у 4 місцях: `get_user_expenses`, `get_all_expenses`, `get_expenses_by_center`, `app.js`).
  - **Веб:** кілька файлів / «додати ще» перед відправкою; вантажити всі частини.
  - **Взаємодія з A1:** валідацію «це чек?» робити по всьому набору (якщо жодна частина не схожа на чек → відхилити).
  - Файли: `handlers/receipts.py`, `handlers/states.py`, `handlers/receipt_callbacks.py`, `ai_service.py`, `schema.sql`, `database.py`, `webapp.py`, `static/js/app.js`, `templates/index.html`.
- [ ] **D2. Один чек → кілька категорій.** Кілька рядків `expenses` зі спільним `group_id VARCHAR(64) NULL` (+ `INDEX`) — простіше для звітів/бюджетів; `NULL` для звичайних (не-групових) витрат. Фото (D1) — на групу (спільні для всіх рядків `group_id`). Редагування/видалення групи оперує всіма рядками з цим `group_id`. UI: кнопка «Розділити на категорії», рівний розподіл за замовчуванням + ручне коригування.

### E. PDF-звіти
- [ ] **E1.** Ендпоінт `GET /api/reports/pdf?center_id=&month=` (для ЦН і адміна). Генерація через `reportlab`: таблиця витрат за період + підсумки по категоріях, **без скріншотів чеків**. Кнопка «📄 Звіт PDF» у веб-формі. Файли: `webapp.py`, новий `report_service.py`, `requirements.txt`, `static/js/app.js`, `templates/`.

### F. UX веб-форми
- [x] **F1. Камера/галерея.** ✅ Прибрано атрибут `capture` з `#f-file` — браузер/ОС самі пропонують «Камера / Галерея / Файл» (iOS, Android, десктоп). Один інпут, без дублювання.
- [x] **F2. Закриття модалок по Esc і кліку поза вікном.** ✅ `initModalDismiss()` у `app.js` (receipt, admin-budgets, my-budget, settings, form) та `initAdminModalDismiss()` у `admin.js` (center, category, user). Клік по backdrop перевіряється разом із `mousedown`/`touchstart`, щоб виділення тексту не закривало форму. Додано `closeMyBudgetModal()` / `closeSettingsModal()` замість inline-обробників.
- [x] **F3. Свайп між витратами у формі.** ✅ `initFormSwipe()`: `touchstart/touchend` на `#modal .modal-content`; свайп вліво → наступна, вправо → попередня. Умови: `|dx| ≥ 60px`, `|dy| ≤ 50px`, тривалість ≤ 800 мс, лише коли видимі кнопки prev/next (редагування існуючої витрати).
- [x] **F4. Кнопки дій у модалках — зверху.** ✅ Клас `.modal-actions-top` (sticky, з `border-bottom`) у `index.html` (форма витрати, налаштування, «Мій бюджет», адмін-модалка) та `admin.html` (ЦН, категорії, користувачі). `.modal-content` отримав `max-height: calc(100vh - 80px); overflow-y: auto` — довгі модалки прокручуються, а кнопки завжди видно. Inline-обробники замінено на `closeForm/closeSettingsModal/closeMyBudgetModal/closeAdminModal`.

### G. Планування бюджетів користувачами + затвердження адміном
- [ ] **G1. Заявки на бюджет (окрема `budget_requests`).** Користувач ЦН вносить план бюджету по категоріях на місяць → статус `pending`. Адмін у кабінеті бачить заявки (знак оклику на кнопці вкладки «Заявки на бюджет»), затверджує (може скоригувати суму)/відхиляє з `reject_reason` → після затвердження сума записується в `budgets` через `set_center_budget` (в одній транзакції зі зміною статусу заявки).
  - Схема `budget_requests`: `id`, `center_id`, `category_id`, `month`, `amount`, `proposed_by`, `status ENUM('pending','approved','rejected')`, `reviewed_by`, `reviewed_at`, `reject_reason`, `created_at`. `budgets` не змінюється (лишається «тільки затверджене»).
  - Дозволено кілька `pending` на одну (center, category, month). Заявка на категорію з наявним `approved` — після схвалення заміняє суму. При затвердженні однієї заявки — **авто-відхиляти інші `pending`** на ту саму (center, category, month) з `reject_reason` «Затверджено іншу заявку».
  - Сповіщення: при поданні — адміну в бот; при рішенні — юзеру в бот (окремо від B3).
  - Файли: `schema.sql`, `database.py`, `webapp.py`, `static/js/app.js`, `static/js/admin.js`, `templates/admin.html`.
